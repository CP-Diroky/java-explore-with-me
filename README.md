# Explore With Me

**Explore With Me (EWM)** — учебный Java-проект с REST API для поиска и организации событий. Пользователи могут просматривать мероприятия, создавать собственные события, подавать заявки на участие, оставлять комментарии и оценивать их. Администратор управляет категориями, пользователями, подборками и модерацией контента.

Приложение состоит из **основного сервиса** и **отдельного сервиса статистики просмотров**. Для хранения данных используются две базы PostgreSQL.

## Функциональность

### События

- Создание и редактирование событий пользователями.
- Просмотр опубликованных событий и детальной информации о мероприятии.
- Поиск и фильтрация по тексту, категориям, платности, диапазону дат и наличию свободных мест.
- Сортировка и постраничная выдача результатов.
- Административная модерация и изменение состояния событий.
- Просмотр событий, созданных определённым пользователем.

### Участие в событиях

- Подача заявки на участие в событии и просмотр своих заявок.
- Отмена собственной заявки.
- Просмотр организатором заявок на его событие.
- Подтверждение или отклонение заявок организатором.

### Категории и подборки

- Просмотр категорий и получение категории по идентификатору.
- Создание, изменение и удаление категорий администратором.
- Просмотр подборок событий, включая закреплённые.
- Создание, изменение и удаление подборок администратором.

### Комментарии и реакции

- Добавление комментариев к опубликованным событиям.
- Редактирование и удаление собственных комментариев.
- Получение комментариев к событию с сортировкой и пагинацией.
- Реакции пользователей на комментарии.
- Административное изменение статуса и удаление комментариев.

### Статистика просмотров

- Сохранение информации об обращениях к эндпоинтам (сервис, URI, IP-адрес, время).
- Получение количества просмотров за указанный период.
- Фильтрация по URI и возможность учитывать только уникальные IP-адреса.
- Обмен данными между основным сервисом и сервисом статистики через HTTP-клиент.

## Архитектура

Проект включает два приложения Spring Boot:

- **`main-service`** — бизнес-логика событий, пользователей, заявок, категорий, подборок и комментариев. Для хранения данных использует БД `ewmdb`.
- **`stats-server`** — приём и агрегирование информации о посещениях; хранит статистику в отдельной БД `statsdb`.

Модуль `stats` также содержит:

- **`stats-client`** — HTTP-клиент, через который основной сервис обращается к статистике.
- **`stats-dto`** — общие DTO для взаимодействия компонентов статистики.

Контроллеры основного сервиса сгруппированы по назначению: **Public** — публичное API, **Private** — операции от имени пользователя с указанием `userId`, **Admin** — административные операции. Это логическое разделение маршрутов; оно само по себе не означает наличия настроенной аутентификации.

## REST API

Ниже приведены основные группы эндпоинтов. Полные контракты запросов и ответов описаны в OpenAPI-спецификациях репозитория.

| Раздел | Методы и маршруты | Назначение |
| --- | --- | --- |
| Публичные события | `GET /events`, `GET /events/{id}` | Поиск, фильтрация и просмотр событий |
| События пользователя | `GET`, `POST /users/{userId}/events` | Список и создание событий |
| Событие пользователя | `GET`, `PATCH /users/{userId}/events/{eventId}` | Просмотр и изменение своего события |
| Модерация событий | `GET /admin/events`, `PATCH /admin/events/{eventId}` | Поиск и управление событиями |
| Публичные категории | `GET /categories`, `GET /categories/{catId}` | Просмотр категорий |
| Управление категориями | `POST /admin/categories`, `PATCH`, `DELETE /admin/categories/{catId}` | Создание, изменение, удаление |
| Публичные подборки | `GET /compilations`, `GET /compilations/{compId}` | Просмотр подборок |
| Управление подборками | `POST /admin/compilations`, `PATCH`, `DELETE /admin/compilations/{compId}` | Управление подборками |
| Пользователи | `GET`, `POST /admin/users`, `DELETE /admin/users/{userId}` | Управление пользователями |
| Заявки участника | `GET`, `POST /users/{userId}/requests` | Получение и подача заявок |
| Отмена заявки | `PATCH /users/{userId}/requests/{requestId}/cancel` | Отмена участия |
| Заявки организатора | `GET`, `PATCH /users/{userId}/events/{eventId}/requests` | Просмотр и изменение статусов заявок |
| Публичные комментарии | `GET /comments/{eventId}` | Получение комментариев события |
| Комментарии пользователя | `POST /users/{userId}/comments/{eventId}` | Добавление комментария |
| Изменение комментария | `PATCH`, `DELETE /users/{userId}/comments/{comId}` | Управление своим комментарием |
| Реакции | `PATCH /users/{userId}/comments/{comId}/reaction` | Реакция на комментарий |
| Модерация комментариев | `PATCH`, `DELETE /admin/comments/{comId}` | Статус и удаление комментария |
| Статистика | `POST /hit`, `GET /stats` (порт `9090`) | Сохранение и получение посещений |

Пример запроса к публичному API:

```bash
curl "http://localhost:8080/events?from=0&size=10"
```

Для точных DTO, параметров и кодов ответов см. [`ewm-main-service-spec.json`](ewm-main-service-spec.json) и [`ewm-stats-service-spec.json`](ewm-stats-service-spec.json). В папке [`postman`](postman/) находятся материалы для проверки API.

## База данных

В основном сервисе используются следующие таблицы:

| Таблица | Содержимое |
| --- | --- |
| `users` | Пользователи |
| `categories` | Категории мероприятий |
| `events` | События, их инициаторы, статус и параметры |
| `requests` | Заявки на участие и их статусы |
| `compilations` | Подборки событий |
| `compilation_events` | Связь подборок и событий (многие ко многим) |
| `comments` | Комментарии к событиям |
| `comment_reactions` | Реакции пользователей на комментарии |

Связи между основными сущностями реализованы через внешние ключи. Для заявок, подборок событий и реакций используются ограничения уникальности. Сервис статистики хранит данные отдельно от основного приложения.

## Запуск проекта

**Требования:** JDK 21, Maven, Docker с Docker Compose.

1. Клонировать репозиторий:

   ```bash
   git clone https://github.com/CP-Diroky/java-explore-with-me.git
   cd java-explore-with-me
   ```

2. Собрать Maven-модули:

   ```bash
   mvn clean package -DskipTests
   ```

3. Запустить контейнеры:

   ```bash
   docker compose up --build
   ```

   Сборка Maven выполняется **перед** запуском Docker, поскольку Dockerfile копируют JAR-файлы из каталогов `target`.

После запуска:

- Основной API: `http://localhost:8080`
- Сервис статистики: `http://localhost:9090`

Остановить и удалить контейнеры:

```bash
docker compose down
```

Согласно `docker-compose.yml`, поднимаются четыре контейнера: `ewm-service`, `stats-server`, `ewm-db`, `stats-db`.
